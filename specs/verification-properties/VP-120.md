# VP-120: Block-Reason Retry Instruction Is a Single Unified Template Independent of the Original Tool Name; Shard-Seal-Write Failure (Steps a-b) Fails Loud as HookResult::Error (E-SHD-001)

## Property Statement

The observable outcome of a roll is a deterministic, actionable `Block` on the normal path and a
loud `Error` on the failure path — never a silent success and never a generic message.

1. **Unified retry wording, independent of tool name (CORRECTED, F-P2-002/F-P2-003).** The block
   reason's retry instruction is a SINGLE, FIXED, UNIFIED template — the SAME wording regardless of
   the original blocked tool (BC-1.18.006 §Postcondition 2 CORRECTED, §Invariant 4): both tool cases
   are named WITHIN the same text ("if you used `Edit`/`MultiEdit`, your `old_string` will no longer
   match — reissue as a fresh `Write` containing ONLY your new entry; if you used `Write`, recompute
   `content` to contain ONLY your new entry"), and both converge on the single instruction "recompute
   against the CURRENT (post-roll, empty) file — do not resubmit your original payload unchanged."
   The reason text always names the artifact, the cap in bytes, and the now-empty-current-shard fact.
   It is never chosen per-tool (the withdrawn v1.0 divergent-wording model), never randomized, never
   omitted, never the generic "write failed, try again." The withdrawn v1.1 "if you used `Write`,
   simply retry unchanged" branch is specifically NOT produced (it deadlocks under the per-tool
   `projected_size = len(content)` formula — BC-1.18.005 §PC3).

2. **Block is the only normal-path variant.** For a normal (non-crash) over-cap write, the gate
   returns `HookResult::Block` — never `Continue` (which would permit an over-cap write) and never
   `Error` (a normal rotation is not an error) (BC-1.18.006 §Invariant 1).

3. **Shard-seal-write failure fails loud.** If the staged roll's steps (a)-(b) fail before the sealed
   shard is durably published (permission error, disk full during the sealed-shard COPY publish), the
   gate returns `HookResult::Error` (taxonomy `E-SHD-001`, description refined to "shard-seal-write
   failure"), NOT `Block` and NOT `Continue`; no shard-index entry is published and the canonical file
   is left COMPLETELY untouched in its exact pre-roll state (BC-1.18.006 §EC-003 / §Postcondition 1
   steps (a)-(b) partial-failure). (The later-step crash points — step (c) E-SHD-006 and step (d)
   E-SHD-007 — are SELF-HEALING, not fail-loud, and are covered by VP-138/VP-139; only steps (a)-(b)
   fail loud, since nothing has changed on disk yet.)

4. **Two-template determinism (EXTENDED, F-C2-P3-001 / EC-021, BC-1.18.006 v1.7 Invariant 4
   adjudication).** BC-1.18.006 v1.7 RESCOPED §Invariant 4 from "a single, fixed template" to "one
   fixed template PER OVER-CAP CASE." There are exactly two over-cap cases, and template selection is
   a PURE FUNCTION of which one fires — never tool-name-dependent WITHIN either case, and no third
   wording ever appears:
   - **Over-cap WITH content** (the staged four-step roll of facet 1 runs): the gate selects the
     unified rotate-and-retry template.
   - **Over-cap WITHOUT content** (§Postcondition 1's empty-canonical short-circuit — the size trigger
     fires but the canonical file is already 0 bytes, so `execute_roll` returns `Ok(None)`: no sealed
     shard published, no index entry appended): the gate selects the DISTINCT
     `build_empty_roll_retry_block_reason` template (§Postcondition 2's "Empty-canonical retry
     template" clause), instructing the agent to recompute or split its payload rather than retry
     against a shard that was already empty before this call.
   These two templates are never interchangeable and no code path may select a third wording.

|-----|--------|------|----------|--------|
| Unified retry wording (tool-independent) | unit-test | Rust `#[test]`, asserting the SAME template for every tool input | reason text is byte-identical for `Edit`/`MultiEdit`/`Write` inputs; names both tool cases, the artifact, the byte cap, and the empty-current fact; never the withdrawn "simply retry unchanged" branch | feasible-pending-harness (F4 code) |
| Fail-loud shard-seal-write error | unit-test | Rust `#[test]` with an injected sealed-shard-write-failure FS (steps a-b) | outcome is `Error` (E-SHD-001), not Block/Continue; no index entry written; canonical byte-identical to pre-roll | feasible-pending-harness (F4 code) |
| **NEW (EC-021) Two-template determinism** | unit-test | Rust `#[test]`, table-driven over the `Ok(None)` empty-canonical short-circuit (`Edit`/`MultiEdit` and `Write` triggers) | asserts the DISTINCT `build_empty_roll_retry_block_reason` template is selected (never the unified template); no shard file or index entry is produced | feasible-pending-harness (F4 code) |

### Why unit-test

The wording is a pure total function that IGNORES the tool name (one fixed template) and the
fail-loud path is a single injected error condition on the staged roll's steps (a)-(b) — a
hand-crafted table (all three tool inputs → identical text; injected seal-write failure → `Error`)
gives exhaustive coverage with no value space a generator would broaden. This matches VP-131's
fail-loud-leg rationale for the symmetric B1 path.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/shard_block_message_test.rs
// VP-120: BC-1.18.006 PC2(CORRECTED unified)/INV1/INV4/EC-003(E-SHD-001)

#[test]
fn test_BC_1_18_006_PC2_retry_wording_is_a_single_unified_template_independent_of_tool() {
    let msg_edit  = shard_manager::block_reason(Tool::Edit,  "burst-log", cap = 49_152);
    let msg_multi = shard_manager::block_reason(Tool::MultiEdit, "burst-log", cap = 49_152);
    let msg_write = shard_manager::block_reason(Tool::Write, "burst-log", cap = 49_152);
    // CORRECTED: byte-identical template regardless of the original tool (INV4).
    assert_eq!(msg_edit, msg_multi);
    assert_eq!(msg_edit, msg_write);
    // the unified template names both tool cases, the artifact, the byte cap, and the empty-current fact:
    assert!(msg_edit.contains("if you used `Edit`") && msg_edit.contains("if you used `Write`"));
    assert!(msg_edit.contains("49152") && msg_edit.contains("burst-log") && msg_edit.contains("empty"));
    // the withdrawn deadlock-prone branch is NOT produced:
    assert!(!msg_write.contains("simply retry unchanged"));
}

#[test]
fn test_BC_1_18_006_EC003_shard_seal_write_failure_is_error_not_block_canonical_untouched() {
    let fs = MockFs::failing_sealed_shard_write();    // steps (a)-(b): sealed-shard copy publish fails
    let before = fs.read("decision-log.md");
    let r = shard_manager::staged_roll("decision-log", &fs);
    assert!(matches!(r, HookResult::Error { .. }));   // E-SHD-001 (shard-seal-write failure), fail-loud
    assert!(!matches!(r, HookResult::Block { .. } | HookResult::Continue));
    assert!(fs.no_index_written());
    assert_eq!(fs.read("decision-log.md"), before);   // canonical completely untouched
}

#[test]
fn test_BC_1_18_006_EC021_empty_canonical_short_circuit_selects_distinct_template() {
    for tool in [Tool::Edit, Tool::MultiEdit, Tool::Write] {
        let cx = DispatchHarness::with_cycle_fixture(current_bytes = 0, cap = 49_152);
        let result = cx.dispatch_write_with_tool(tool, "decision-log.md", payload = 60_000);
        // EC-021: canonical already 0 bytes, size trigger fires against an already-empty shard
        assert!(matches!(result, HookResult::Block { .. }));
        let reason = result.block_reason();
        assert!(reason.contains("already empty"));       // DISTINCT empty-canonical template
        assert!(!reason.contains("if you used `Edit`") && !reason.contains("if you used `Write`"));
        // never the unified rotate-and-retry template (facet 1)
        assert!(!cx.path_exists("decision-log.0001.md"));  // no shard published
        assert!(cx.read_shard_index("decision-log").shards.is_empty()); // no index entry
    }
}
```
