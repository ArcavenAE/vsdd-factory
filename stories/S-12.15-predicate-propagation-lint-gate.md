## Problem Statement

When a spec predicate changes (e.g., drain-GC criterion in ADR §Decision), that change must
propagate to EVERY sibling location that references or implements the predicate:

1. **ADR §Decision ↔ ADR §Files-to-Change:** If §Decision changes the mechanism, §Files-to-Change
   implementer directives for the affected files must be updated to match.
2. **ADR §Decision ↔ BC postconditions:** If §Decision introduces a new error code or mechanism,
   BC §Postconditions / §Error Codes referencing it must be updated.
3. **BC postconditions ↔ VP catalog rows:** If a BC postcondition changes, VP-INDEX catalog
   annotations for VPs that cite that BC must be updated with a version bump note.
4. **ADR §Error Code Semantics ↔ error-taxonomy.md:** If ADR introduces or re-scopes an error
   code, error-taxonomy.md Message-Format cell must reflect the canonical form.

Currently, no mechanical gate enforces these propagation invariants. Every cascade requires a
manual orchestrator global grep, which is both slow and error-prone.

## Acceptance Criteria

**AC-001 (§Decision ↔ §Files-to-Change propagation check):**
Given: An ADR document is edited, and the edit changes a predicate in §Decision.
When: The propagation-lint gate runs.
Then: The gate verifies the corresponding §Files-to-Change row for each affected file/mechanism
has been updated in the same burst. If any §Files-to-Change row still references the old
predicate, the gate exits non-zero.

**AC-002 (BC ↔ VP-INDEX catalog row propagation check):**
Given: A BC file is edited and its version is bumped.
When: The propagation-lint gate runs.
Then: The gate verifies the VP-INDEX catalog row for every VP that cites that BC includes a
version-bump annotation in the same burst. If any VP-INDEX catalog row annotation is stale,
the gate exits non-zero.

**AC-003 (ADR/BC error code ↔ error-taxonomy.md consistency check):**
Given: An error code (E-SHD-NNN) is introduced or re-scoped in an ADR or BC file.
When: The propagation-lint gate runs.
Then: The gate verifies error-taxonomy.md contains a matching entry with the canonical
Message-Format form. If any error code is present in the ADR/BC but absent or mis-anchored in
error-taxonomy.md, the gate exits non-zero.
